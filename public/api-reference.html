API Reference

REST API

All requests are authenticated using your API key. The SDK handles enrollment and verification automatically — use the REST API directly for backend integrations and the reputation endpoint.

Base URL https://api.vouchflow.dev/v1
POST /v1/enroll
Enroll a device

Registers a device's public key with Vouchflow. Called automatically by the iOS and Android SDKs on first use. Call directly only if implementing a custom SDK or testing enrollment flows from your backend.

⚠ App Attest required (iOS) Enrollment on iOS requires the App Attest entitlement. Without it, the platform attestation step fails and confidence is capped at medium.
Request body
public_key string Required Base64-encoded public key generated by the Secure Enclave (iOS) or Android Keystore. The private key never leaves the chip.
attestation string Required Platform attestation blob. Apple App Attest on iOS; Play Integrity API on Android. Used to verify request originated from genuine, unmodified SDK on real hardware.
platform enum Required One of ios, android.
network_opt_in boolean Optional Default false. Set to true to contribute this device's verification history to the cross-app reputation graph. Requires user consent surfaced by your app.
Response
device_id string Scoped device identifier. Unique per app by default; shared across network participants when network_opt_in is true.
enrolled_at string ISO 8601 timestamp of enrollment.
attestation_level enum One of hardware, software, none. Reflects whether platform attestation succeeded.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/enroll \
  -H "Authorization: Bearer vsk_sandbox_••••" \
  -H "Content-Type: application/json" \
  -d '{
    "public_key": "MFkwEwYHKoZIzj0CAQY...",
    "attestation": "o2NmbXRvYXBwbGUt...",
    "platform": "ios",
    "network_opt_in": false
  }'
200 OK
RESPONSE
{
  "device_id": "dvc_01HZXK9M4P3R8TQYF6N2W",
  "enrolled_at": "2026-04-11T09:14:22Z",
  "attestation_level": "hardware"
}
POST /v1/verify
Verify a device

Validates a signed challenge-response from an enrolled device. Returns a confidence signal proving the same physical device is present. This is the core API call — everything else supports it.

Request body
device_id string Required The device_id returned at enrollment.
challenge string Required Single-use challenge string issued by your backend. Must not be reused — each verification requires a fresh challenge.
signature string Required Base64-encoded signature of the challenge, produced by the Secure Enclave or Keystore private key.
idempotency_key string Optional Supply a unique key to safely retry a request without triggering a duplicate verification. Valid for 24 hours.
Response
verified boolean true if signature is valid and confidence meets your configured threshold.
confidence enum One of high, medium, low. Reflects hardware attestation level, biometric type, and device history.
platform enum ios or android.
biometric string Biometric method used. One of face_id, touch_id, biometric (Android), none.
device_age_days integer Days since this device_id was first enrolled. 0 on first verification.
session_duration_ms integer Time in milliseconds from SDK call to verified result.
Confidence thresholds You can configure a minimum confidence level in your dashboard. Verifications below the threshold return verified: false with the actual confidence value still present — allowing you to decide how to handle degraded cases.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/verify \
  -H "Authorization: Bearer vsk_live_••••" \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "dvc_01HZXK9M4P3R8TQYF6N2W",
    "challenge": "ch_9f2a8e1b4d3c7f0e",
    "signature": "MEUCIQDx7mN3p...",
    "idempotency_key": "idem_signup_user_8821"
  }'
200 OK
RESPONSE
{
  "verified": true,
  "confidence": "high",
  "platform": "ios",
  "biometric": "face_id",
  "device_age_days": 142,
  "session_duration_ms": 1840
}
200 OK — low confidence
DEGRADED RESPONSE
{
  "verified": false,
  "confidence": "low",
  "platform": "android",
  "biometric": "none",
  "device_age_days": 0
}
GET /v1/device/:device_id
Retrieve a device

Returns the enrollment state and verification history for a single device. Useful for auditing, support tooling, and building device management UIs.

Path parameters
device_id string Required The device identifier returned at enrollment.
Response
device_id string The device identifier.
platform enum ios or android.
enrolled_at string ISO 8601 enrollment timestamp.
verification_count integer Total verifications completed for this device.
last_verified_at string ISO 8601 timestamp of most recent successful verification.
attestation_level enum hardware, software, or none.
REQUEST
curl https://api.vouchflow.dev/v1/device/dvc_01HZXK9M \
  -H "Authorization: Bearer vsk_live_••••"
200 OK
RESPONSE
{
  "device_id": "dvc_01HZXK9M4P3R8TQYF6N2W",
  "platform": "ios",
  "enrolled_at": "2025-11-20T14:02:11Z",
  "verification_count": 38,
  "last_verified_at": "2026-04-11T09:14:22Z",
  "attestation_level": "hardware"
}
POST /v1/reputation
Query device reputation

Returns cross-app reputation signals for a device that has opted into the Vouchflow Network. A device verified across many apps over a long period with no anomalies has a stronger reputation signal than a device that appeared recently.

Network participation required This endpoint returns meaningful data only for devices enrolled with network_opt_in: true. Devices in isolated mode return a minimal response with no cross-app signals.
Request body
device_id string Required The network-scoped device identifier.
Response
reputation_score integer 0–100. Composite score derived from device age, cross-app verification count, anomaly history, and reinstall events.
network_app_count integer Number of distinct Vouchflow-integrated apps this device has verified with.
anomaly_flags array List of anomaly signals detected. May include rapid_app_spread, reinstall_detected, attestation_downgrade.
first_seen_at string ISO 8601 timestamp of the device's earliest known network enrollment.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/reputation \
  -H "Authorization: Bearer vsk_live_••••" \
  -H "Content-Type: application/json" \
  -d '{ "device_id": "dvc_01HZXK9M4P3R8TQYF6N2W" }'
200 OK
RESPONSE
{
  "reputation_score": 91,
  "network_app_count": 14,
  "anomaly_flags": [],
  "first_seen_at": "2025-09-03T07:44:01Z"
}
Errors

Vouchflow uses standard HTTP status codes. All error responses include a machine-readable code and a human-readable message.

Error codes
enrollment_failed Platform attestation did not succeed. Check App Attest entitlement (iOS) or Play Integrity configuration (Android).
invalid_signature The challenge signature could not be verified against the enrolled public key. Device may have been re-keyed or tampered with.
challenge_expired Challenges are single-use and expire after 5 minutes. Generate a fresh challenge and retry.
challenge_already_used This challenge has already been consumed. Use an idempotency_key to safely retry a request.
device_not_found No device matching the provided device_id exists in this account's scope.
minimum_confidence_unmet Verification succeeded cryptographically but confidence fell below your configured threshold.
network_not_enrolled Reputation endpoint called for a device not enrolled in the Vouchflow Network.
rate_limit_exceeded Too many requests. Back off and retry using exponential backoff. Limits are per API key.
unauthorized API key missing, malformed, or scoped incorrectly. Sandbox keys cannot call production endpoints.
Error response shape 
{
  "error": {
    "code":    "challenge_expired",
    "message": "Challenge has expired. Generate a new one.",
    "status":  400
  }
}
