API Reference

REST API

All requests are authenticated using your API key. The official SDKs (iOS, Android, Web) handle enrollment and verification ceremonies automatically — use them instead of calling these endpoints directly. Direct REST API usage is for: server-side reputation lookups (GET /device/:token/reputation), webhook management, or building custom SDKs for unsupported platforms.

Base URL https://api.vouchflow.dev/v1
POST /v1/enroll
Enroll a device

Registers a device's public key with Vouchflow. Called automatically by the iOS, Android, and Web SDKs on first use.

⚠️ Most customers should never call this endpoint directly The official SDKs handle enrollment automatically. Direct calls bypass SDK state management and can cause duplicate enrollments or attestation failures. Only call this endpoint if you're:
  • Building a custom SDK for an unsupported platform (e.g., React Native, Flutter, Unity)
  • Running automated backend tests
  • Debugging enrollment issues server-side
For standard integrations, use sdk.enroll() (iOS/Android) or the SDK's automatic enrollment on first verify() call.
App Attest required for high confidence (iOS) Enrollment on iOS requires the App Attest entitlement for confidence: high. Without it, the platform attestation step fails and confidence is capped at medium.
Request body
public_key string Required Base64-encoded public key generated by the Secure Enclave (iOS) or Android Keystore. The private key never leaves the chip. Web: pass an empty string — the server extracts the COSE public key from the WebAuthn attestation_object.
attestation object Optional Per-device hardware attestation proof. iOS: { token, key_id } — Apple App Attest CBOR object + credential ID. Android: { cert_chain } — Keystore Attestation X.509 chain (leaf-first, each cert base64-DER) rooted in the Google Hardware Attestation Root CA. Web: { webauthn_attestation: { attestation_object, client_data_json } } — both base64url-encoded directly from navigator.credentials.create(). Omit on Simulator / emulator / unsupported devices; the server falls back to confidence_ceiling: medium.
platform enum Required One of ios, android, web.

Network participation is a customer-level setting, not a per-enroll flag — set it via PATCH /v1/customers/:id with {"network_opt_in": true|false}, or toggle it in Settings → Account. It defaults to true for new customers (Private mode opts you out).

Response
device_id string Scoped device identifier. Unique per app by default; shared across network participants when network_opt_in is true.
enrolled_at string ISO 8601 timestamp of enrollment.
attestation_level enum One of hardware, software, none. Reflects whether platform attestation succeeded.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/enroll \
  -H "Authorization: Bearer vsk_sandbox_••••" \
  -H "Vouchflow-API-Version: 2026-04-01" \
  -H "Content-Type: application/json" \
  -d '{
    "public_key": "MFkwEwYHKoZIzj0CAQY...",
    "attestation": "o2NmbXRvYXBwbGUt...",
    "platform": "ios"
  }'
200 OK
RESPONSE
{
  "device_id": "dvc_01HZXK9M4P3R8TQYF6N2W",
  "enrolled_at": "2026-04-11T09:14:22Z",
  "attestation_level": "hardware"
}
POST /v1/verify
Verify a device

Initiates a verification ceremony. The SDK calls this automatically when you invoke sdk.verify() — you should use the SDK method rather than calling this endpoint directly. For custom SDK implementations or backend testing, this endpoint starts a verification session and returns a challenge that must be signed by the device within 60 seconds.

SDK handles this automatically Call await vouchflow.verify() (iOS/Android/Web) instead of using this REST endpoint directly. The SDK manages the full ceremony: init → sign challenge → complete → return result.
Request body
device_id string Required The device_id returned at enrollment.
challenge string Required Single-use challenge string issued by your backend. Must not be reused — each verification requires a fresh challenge.
signature string Required Base64-encoded signature of the challenge, produced by the Secure Enclave or Keystore private key. Web: send as signed_challenge on the /complete call — the raw WebAuthn assertion signature, base64.
client_data_json string Web only Base64 of the WebAuthn clientDataJSON. Presence of this field switches the backend onto the WebAuthn verification path; the server reads the origin from here and rejects on mismatch.
authenticator_data string Web only Base64 of the WebAuthn authenticatorData. Server parses the UV flag, RP ID hash, and signature counter from this.
credential_id string Web only Base64url-encoded WebAuthn credential ID. Identifies which credential on the device was used.
idempotency_key string Optional Supply a unique key to safely retry a request without triggering a duplicate verification. Valid for 24 hours.
Web platform mismatch The server rejects calls with WebAuthn fields against an enrolled ios / android device (and vice versa) with 422 platform_mismatch. Each device is single-platform — re-enroll under platform: web if you migrate a user across platforms.
Response
verified boolean true if signature is valid and confidence meets your configured threshold.
confidence enum One of high, medium, low. Reflects hardware attestation level, biometric type, and device history.
platform enum ios or android.
biometric string Biometric method used. One of face_id, touch_id, biometric (Android), none.
device_age_days integer Days since this device_id was first enrolled. 0 on first verification.
session_duration_ms integer Time in milliseconds from SDK call to verified result.
device_token string Opaque token identifying this device. Pass to GET /v1/device/:device_token/reputation from your server to query trust signals. Never log or expose client-side.
session_id string Identifier for this verification session. Matches the session_id in webhook payloads.
Confidence thresholds You can configure a minimum confidence level in your dashboard. Verifications below the threshold return verified: false with the actual confidence value still present — allowing you to decide how to handle degraded cases.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/verify \
  -H "Authorization: Bearer vsk_live_••••" \
  -H "Vouchflow-API-Version: 2026-04-01" \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "dvc_01HZXK9M4P3R8TQYF6N2W",
    "challenge": "ch_9f2a8e1b4d3c7f0e",
    "signature": "MEUCIQDx7mN3p...",
    "idempotency_key": "idem_signup_user_8821"
  }'
200 OK
RESPONSE
{
  "verified": true,
  "confidence": "high",
  "platform": "ios",
  "biometric": "face_id",
  "device_age_days": 142,
  "session_duration_ms": 1840,
  "device_token": "dvt_01HZXKBM9F2R4QWEP7N3J",
  "session_id": "ses_01HZXK9M4P3R8TQYF6N2W"
}
200 OK — low confidence
DEGRADED RESPONSE
{
  "verified": false,
  "confidence": "low",
  "platform": "android",
  "biometric": "none",
  "device_age_days": 0
}
POST /v1/sign web beta
Initiate a payload-signing session

Starts a high-assurance signing session over an arbitrary canonicalized JSON payload. Returns a server-issued challenge that must be signed by the device's WebAuthn credential and submitted to POST /v1/sign/:session_id/complete within 60 seconds.

SDK handles this automatically Call await vouchflow.signPayload({ payload, context }) (Web SDK) instead of using this REST endpoint directly. The SDK manages the full ceremony: init → WebAuthn assertion → complete → return JWS assertion. For mobile platforms (iOS/Android), use native signing APIs.
Idempotency strongly recommended Pass a unique idempotency_key per logical signing operation. The SDK generates this automatically. If implementing a custom SDK, generate a cryptographically random 16-byte value per call. Without it, network retries on 5xx errors would mint multiple valid JWS assertions with different iat over the same payload.
Request body
device_token string Required The device token returned at enrollment. Must reference a platform: web device.
context string Required Audited per session and echoed into the JWS assertion. Free-form (e.g. mandate_signing, delta_mandate_signing, approval).
canonicalized_payload string Required RFC 8785 JCS canonicalized JSON string produced client-side. The server stores its SHA-256 and embeds that hash (never the payload itself) in the JWS assertion.
minimum_confidence enum Optional One of high (default), medium, low. The session is refused with 422 verification_impossible if the device's ceiling is below this.
idempotency_key string Optional Replay-safe key — if the same key is seen within 24 h the original {session_id, challenge} response is returned.
Response
session_id string Opaque ID used in the /complete path and in webhook payloads.
challenge string Base64-encoded 32-byte random challenge. Pass this as the WebAuthn challenge.
expires_at string ISO 8601 — 60 seconds after issue.
payload_sha256 string Hex SHA-256 of canonicalized_payload. Echoed for client-side sanity-checking.
session_state enum Always INITIATED on success.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/sign \
  -H "Authorization: Bearer vsk_sandbox_••••" \
  -H "Vouchflow-API-Version: 2026-04-01" \
  -H "Content-Type: application/json" \
  -d '{
    "device_token": "dvt_01HZXKBM9F2R4QWEP7N3J",
    "context": "mandate_signing",
    "canonicalized_payload": "{\"id\":\"mand_abc\",\"scope\":\"send\",\"v\":1}",
    "minimum_confidence": "high",
    "idempotency_key": "sk_…"
  }'
200 OK
RESPONSE
{
  "session_id": "ses_01HZXK…",
  "challenge": "VHJ1c3R5U3F1aXJlQ2hhbGxlbmdl…",
  "expires_at": "2026-05-10T14:35:00Z",
  "payload_sha256": "abcdef0123…",
  "session_state": "INITIATED"
}
POST /v1/sign/:session_id/complete web beta
Complete a payload-signing session

Submits the WebAuthn assertion produced over the challenge returned by POST /v1/sign. The server validates the assertion (UV flag, origin, signature, RP ID hash, counter), records the verification, and returns a JWS assertion signed by Vouchflow's verifier key. Customers verify this JWS against GET /.well-known/jwks.json; the SDK exposes it as SignResult.assertion.

Automatic idempotency This endpoint is idempotent by design. Once a session is completed, retrying the same request with the same session_id returns the cached response with a 200 status code, not a 409 conflict. This makes network retries safe.
Request body
device_token string Required Must match the device that initiated the session.
signed_challenge string Required Base64-encoded WebAuthn assertion signature.
client_data_json string Required Base64 of clientDataJSON. Server reads origin and rejects on mismatch.
authenticator_data string Required Base64 of authenticatorData. Server parses UV flag, RP ID hash, counter.
credential_id string Required Base64url-encoded WebAuthn credential ID.
Response
verified boolean Always true on a 200 response — failures return 4xx with an error body.
confidence enum high, medium, or low. Computed at completion using the device ceiling and the UV flag.
device_token string Echo of the request value.
signing_device_id string sdv_-prefixed stable per-credential identifier (SHA-256 of the credential ID, truncated). Useful as a fingerprint distinct from device_token.
signed_at string ISO 8601 completion time.
assertion string Vouchflow-signed JWS (compact form: header.payload.signature). Payload claims: v, iss, aud, iat, exp, context, device_token, signing_device_id, confidence, payload_sha256, session_id.
session_id string Echo of the path parameter; matches the sign.complete webhook payload.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/sign/ses_01HZXK…/complete \
  -H "Authorization: Bearer vsk_sandbox_••••" \
  -H "Content-Type: application/json" \
  -d '{
    "device_token": "dvt_01HZXKBM9F2R4QWEP7N3J",
    "signed_challenge": "MEUCIQ…",
    "client_data_json": "eyJ0eXBlIjoid2ViYXV0aG4uZ2V0Iiwi…",
    "authenticator_data": "SZYN5YgOjGh0…",
    "credential_id": "AQIDBAUGBwgJCgsMDQ4PEBESExQVFhc"
  }'
200 OK
RESPONSE
{
  "verified": true,
  "confidence": "high",
  "device_token": "dvt_01HZXKBM9F2R4QWEP7N3J",
  "signing_device_id": "sdv_3f8c2a1d…",
  "signed_at": "2026-05-10T14:30:12Z",
  "assertion": "eyJhbGciOiJFZERTQSIsImtpZCI6IndmLTIwMjYt…",
  "session_id": "ses_01HZXK…"
}
GET /.well-known/jwks.json web beta
Vouchflow verifier JWKS

Public JWK Set for the keys Vouchflow uses to sign POST /v1/sign/:session_id/complete assertions. Verify customer-side using jose's createRemoteJWKSet — the library caches and refreshes on kid miss, and the endpoint sets cache-control: public, max-age=3600, stale-while-revalidate=86400.

Public endpoint No Authorization header required. The set is small (currently one active key plus the previous-rotation key for grace), and Cloudflare caches in front. Customers should not hit this on every assertion — let jose manage the cache.
Response
keys array Array of JWK objects. Each contains kty, kid, alg, use: "sig", and the public-key parameters (e.g. crv, x for EdDSA; crv, x, y for ES256). New keys roll in 14 days before becoming the active signer; the rotated-out key remains in the set for 14 days after rotation.
REQUEST
curl https://api.vouchflow.dev/.well-known/jwks.json
200 OK
RESPONSE
{
  "keys": [
    {
      "kty": "OKP",
      "crv": "Ed25519",
      "kid": "wf-2026-04",
      "alg": "EdDSA",
      "use": "sig",
      "x": "11qYAYKxCrfVS_7TyWQHOg7hcvPapiMlrwIaaPcHURo"
    }
  ]
}
GET /v1/device/:device_token/reputation
Query device reputation

Returns trust signals and the most recent verification record for a device token. Call this from your server after the mobile SDK returns a device_token — never expose your read-scoped key to the mobile client.

Read-scoped key required This endpoint requires a read-scoped API key (vsk_read_...). Write-scoped keys used by the mobile SDK will return 403 insufficient_scope.
Path parameters
device_token string Required The opaque device token returned in the POST /v1/verify response.
Response
device_token string Echo of the requested device token.
first_seen string ISO 8601 timestamp of first enrollment.
last_seen string ISO 8601 timestamp of most recent API activity.
total_verifications integer Total successful verifications for this device across your app.
network_verifications integer Verifications contributed to the cross-app network. 0 for devices not opted in.
anomaly_flags array List of anomaly signals. May include rapid_app_spread, reinstall_detected, attestation_downgrade.
risk_score integer 0–100 composite risk score. Lower is better. Derived from device age, anomaly history, and attestation level.
device_age_days integer Days since this device was first enrolled.
platform enum ios or android.
keychain_persistent boolean true if the device token has persisted across app reinstalls.
network_participant boolean true if the device is opted into the cross-app reputation graph.
last_verification object Most recent completed verification, or null. Contains: confidence (high / medium / low), context, completed_at (ISO 8601), biometric_used, fallback_used.
REQUEST
curl https://api.vouchflow.dev/v1/device/dvt_01HZXKBM9F2R4QWEP7N3J/reputation \
  -H "Authorization: Bearer vsk_read_••••" \
  -H "Vouchflow-API-Version: 2026-04-01"
200 OK
RESPONSE
{
  "device_token": "dvt_01HZXKBM9F2R4QWEP7N3J",

  "last_seen": "2026-04-11T09:14:22Z",
  "total_verifications": 38,

POST /v1/webhooks
Create a webhook endpoint

Registers a URL to receive event notifications. The signing secret is returned once in the response and never again — store it the moment you receive it. Subsequent reads only return metadata. Hard cap of 5 endpoints per customer.

Write-scoped key required Webhook configuration is treated as a write operation. The same write key your SDK uses works here; read-only keys return 403 insufficient_scope.
Request body
url string Required The HTTPS endpoint that will receive POSTs. http://localhost is allowed in sandbox; everything else must be HTTPS.
events array Required Non-empty array of event names this endpoint subscribes to. Currently supported: verification.complete, verification.fallback_complete. Unknown events return 400 invalid_request.
Response (201 Created)
id string Stable identifier for this endpoint. Used in PATCH / DELETE URLs.
url string Echo of the URL you sent.
events array Echo of the events array.
secret string whsec_-prefixed signing secret. Use this to verify the X-Vouchflow-Signature header on inbound requests. Returned only once — there is no way to retrieve it later.
createdAt string ISO 8601 timestamp.
REQUEST
curl -X POST https://api.vouchflow.dev/v1/webhooks \
  -H "Authorization: Bearer vsk_sandbox_••••" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://api.acme.com/webhooks/vouchflow",
    "events": ["verification.complete", "verification.fallback_complete"]
  }'
201 Created
RESPONSE
{
  "id": "clx9k4m...",
  "url": "https://api.acme.com/webhooks/vouchflow",
  "events": ["verification.complete", "verification.fallback_complete"],
  "secret": "whsec_a1b2c3d4...",
  "createdAt": "2026-05-05T18:21:09Z"
}
GET /v1/customers/:id/webhooks
List webhook endpoints

Returns metadata for every webhook endpoint registered to your customer. The :id in the path is decorative — scope is taken from the API key, so the response always reflects the auth'd customer regardless of what's in the URL.

Response
webhooks array Array of objects with id, url, events, createdAt. Secrets are never returned here.
REQUEST
curl https://api.vouchflow.dev/v1/customers/cust_xxx/webhooks \
  -H "Authorization: Bearer vsk_sandbox_••••"
200 OK
RESPONSE
{
  "webhooks": [
    {
      "id": "clx9k4m...",
      "url": "https://api.acme.com/webhooks/vouchflow",
      "events": ["verification.complete"],
      "createdAt": "2026-05-05T18:21:09Z"
    }
  ]
}
PATCH /v1/webhooks/:id
Update a webhook endpoint

Updates the URL and/or the events subscription on an existing endpoint. Body must include at least one of url or events. The signing secret cannot be rotated through this endpoint — delete and recreate to get a new secret.

Request body
url string Optional New HTTPS URL. Same validation rules as create.
events array Optional Replaces the existing events array. Must be non-empty if present.

Returns 404 not_found if the :id doesn't exist or belongs to another customer (no information leak between tenants).

REQUEST
curl -X PATCH https://api.vouchflow.dev/v1/webhooks/clx9k4m... \
  -H "Authorization: Bearer vsk_sandbox_••••" \
  -H "Content-Type: application/json" \
  -d '{ "events": ["verification.complete"] }'
200 OK
DELETE /v1/webhooks/:id
Delete a webhook endpoint

Permanently deletes the endpoint and the full delivery history for it. In-flight retry attempts are dropped. Returns 404 if the endpoint doesn't exist or belongs to another customer.

REQUEST
curl -X DELETE https://api.vouchflow.dev/v1/webhooks/clx9k4m... \
  -H "Authorization: Bearer vsk_sandbox_••••"
204 No Content
Errors

Vouchflow uses standard HTTP status codes. All error responses include a machine-readable code and a human-readable message.

Error codes
enrollment_failed Enrollment could not complete. Check App Attest entitlement (iOS), or that you've registered your Android applicationId and signing-cert SHA-256 in the dashboard before sending Keystore Attestation chains.
invalid_signature The challenge signature could not be verified against the enrolled public key. Device may have been re-keyed or tampered with.
challenge_expired Challenges are single-use and expire after 5 minutes. Generate a fresh challenge and retry.
challenge_already_used This challenge has already been consumed. Use an idempotency_key to safely retry a request.
device_not_found No device matching the provided device_id exists in this account's scope.
minimum_confidence_unmet Verification succeeded cryptographically but confidence fell below your configured threshold.
network_not_enrolled Reputation endpoint called for a device not enrolled in the Vouchflow Network.
rate_limit_exceeded Too many requests. Back off and retry using exponential backoff. Limits are per API key.
unauthorized API key missing, malformed, or scoped incorrectly. Sandbox keys cannot call production endpoints.
Error response shape 
{
  "error": {
    "code":    "challenge_expired",
    "message": "Challenge has expired. Generate a new one.",
    "status":  400
  }
}
